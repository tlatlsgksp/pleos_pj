## 1. 앱 한 줄 소개

> **차가 직접 쓰는 차계부.** 주행거리·연비·주유를 차량 데이터로 자동 기록하고, 차량 내비와 주고받으며 주유소·정비소까지 이어 주는 차량 밀착형 차계부.

## 2. 기획 배경

### 2.1 고객 니즈와 불편한 순간

차를 관리하고 싶은 운전자는 많지만, 관리를 계속하는 운전자는 적다. **기록이 귀찮기 때문이다.**

| 불편한 순간 | 지금 하는 일 | 결과 |
|---|---|---|
| 주유를 마쳤을 때 | 영수증을 보고 금액·주유량·주행거리를 폰에 입력한다 | 몇 번 하다 그만둔다. 연비와 지출 통계가 틀어진다 |
| 정비소에 다녀왔을 때 | 정비 내역을 따로 입력해야 한다 | 대부분 남기지 않는다. 다음 교체 시점을 모른다 |
| 연료가 얼마 안 남았을 때 | 운전 중에 주유소를 찾아 내비를 다시 설정한다 | 주행 중 조작이 위험하고, 비싼 주유소에 들른다 |
| 사고가 났을 때 | 경황이 없어 보험사 번호를 찾는다 | 긴급출동 요청이 늦어진다 |
| 내 차 연비가 좋은 편인지 궁금할 때 | 비교할 기준이 없다 | 운전 습관을 바꿀 동기가 없다 |

시중 모바일 차계부 앱도 같은 한계를 보인다. 앱은 차의 주행거리를 알 수 없어서 **사용자에게 주기적으로 주행거리 입력 알림을 보내야만** 정비 주기를 계산할 수 있다. `[근거 필요: 앱 리뷰·시장 조사 같은 공개 자료의 입력률·이탈률 수치가 있으면 넣는다]`

### 2.2 해결 필요성: 왜 차 안이어야 하는가

모바일 차계부의 한계는 데이터가 사람 손을 거친다는 점이다. 차량 앱은 다르다.

- 총 주행거리, 연료 잔량, 실측 연비, 주행 모드를 **차가 알고 있다.**
- 에어백 전개, 엔진 이상, 오일류·타이어 경고를 **차가 먼저 안다.**
- 어디로 가는지, 언제 도착했는지를 **차량 내비가 안다.**

차곡은 이 데이터로 **기록을 자동화하고**, 기록이 필요한 순간과 정비·주유가 필요한 순간을 **이동 경로와 연결한다.**

## 3. 주요 기능 및 차량 특화 요소

### 3.1 기능 구성

**A. 자동 기록: 차가 쓰는 차계부**

| 기능 | 하는 일 | 차량 특화 요소 |
|---|---|---|
| 주행거리 자동 기록 | 차에 탈 때마다 총 주행거리를 읽어 기록한다. 앱을 처음 켠 시점의 총 주행거리를 기준으로 삼고, 앱을 안 연 기간의 주행도 총 주행거리 차이로 이어 붙인다. 이전 기록은 모바일 차계부에서 가져온다 | Vehicle SDK 총 주행거리 |
| 주행 모드별 연비 | 에코·노멀·스포츠 모드마다 연비를 따로 기록해 "내 차는 어떤 모드에서 연비가 좋은가"를 보여 준다 | Vehicle SDK 주행 모드, 연비 |
| 경로별 기록·운전 점수 | 목적지마다 거리·시간·통행료·연비를 기록한다. 제한속도 준수와 과속 경고로 운전 점수를 매긴다 | NaviHelper 경로 시작·도착 이벤트, 제한속도·과속 경고, AAOS 차속 |
| 주유 기록 안내 | 주유 후 주행거리 초기화와 연료 증가로 주유를 감지하고, 현재 위치로 주유소를 찾아 석유공사(오피넷) 단가로 금액을 미리 채운다. 운전자는 확인만 누른다 | Vehicle SDK 주유 후 거리·연료 %, NaviHelper 현재 위치, 오피넷 |
| 음성 기록 | "엔진오일 교체 8만 원 기록해 줘"처럼 말로 정비·지출을 기록한다 | Gleo AI 앱 연동(조건부), STT SDK(준비 중). 대체: Android 표준 음성인식 |

**B. 내비 쌍방향 연동**

| 기능 | 하는 일 | 차량 특화 요소 |
|---|---|---|
| 주유소 경유 경로 | 남은 주행거리가 기준 미만이면 경로 위 최저가 주유소를 보여 주고, 선택하면 내비 경로에 경유지로 넣는다 | NaviHelper 경유지 추가·도착 예상 잔여 연료, 오피넷 |
| 정비소 방문 자동 기록 | 내비 목적지가 정비소이면 이를 기억한다. 도착 후 다시 시동을 걸면 "어떤 정비를 받으셨나요?"를 묻고, 프리셋 선택으로 기록과 다음 교체 시점을 갱신한다 | NaviHelper 목적지 정보·도착 이벤트 |
| 오토큐·블루핸즈 예약 | 정비 시기가 되면 가까운 오토큐·블루핸즈 예약 페이지로 연결하고, 정비소를 내비 목적지로 보낸다 | NaviHelper 목적지 설정 |

**C. 안전·정비**

| 기능 | 하는 일 | 차량 특화 요소 |
|---|---|---|
| 사고 시 보험사 연락 권유 | 에어백 전개가 감지되면 등록한 보험사의 긴급출동 번호와 사고 대응 순서를 바로 보여 준다 | Vehicle SDK 에어백 전개 |
| 차량 진단 기반 정비 권유 | 엔진 이상, 엔진오일·브레이크액·미션오일 레벨, 타이어 저압, 워셔액 경고를 소모품 교체 주기와 함께 판단해 정비를 권한다 | Vehicle SDK 안전·타이어 도메인 |
| 대여 모드 | 차를 빌려줄 때 켜면 내 기록·개인정보를 숨기고, 대여 기간의 주행거리·주유만 따로 기록해 정산에 쓴다 | Vehicle SDK 총 주행거리·연료 |

**D. 커뮤니티: 같은 차를 타는 사람들**

| 기능 | 하는 일 | 차량 특화 요소 |
|---|---|---|
| 같은 차량 통계·순위 | 같은 차종 운전자들의 평균 연비·주유 주기·월 지출과 내 기록을 비교하고 월간 연비 순위를 보여 준다 | Vehicle SDK VIN으로 차종 자동 식별. 가명화한 요약값만 서버 전송 |
| 차량 꾸미기·모델링 | 내 차종의 3D 모델에 색상·휠·스티커 스킨을 입힌다 | VIN으로 차종 자동 선택 |
| 스킨 마켓·커뮤니티 | 스킨을 사고팔고, 꾸민 차로 순위·커뮤니티 활동을 한다 | 자체 서버 |

### 3.2 주행 중과 정차 중

앱 카테고리는 **Mobility Services**다. 카테고리 정책이 주행 중 허용 예시로 드는 "주행과 관련된 차량 관리", "주유소 탐색"에 맞춰 주행 중에는 최소한의 기능만 연다.

| 상황 | 쓸 수 있는 기능 | 방식 |
|---|---|---|
| 주행 중 | 주유소 경유 제안, 경고·사고 알림 | 큰 카드 한 장과 버튼 두 개("들르기 / 나중에"). 키보드 입력 없음. 음성 기록 |
| 시동 직후 | 주유·정비 기록 확인 | 프리셋 선택 한 번 |
| 정차 중 | 기록 수정, 통계, 순위, 꾸미기, 마켓, 커뮤니티, 설정 | 전체 화면 |

### 3.3 차별점

| | 모바일 차계부 | 차곡 |
|---|---|---|
| 주행거리 | 매일 직접 입력 | 차가 기록 |
| 주유 기록 | 영수증 보고 입력 | 감지 후 확인만 |
| 정비 판단 | 주기 추정 | 주기 + 차량 경고 |
| 주유소·정비소 | 앱에서 검색 후 내비 재설정 | 내비 경로에 바로 경유지 추가 |
| 비교 | 없음 | 같은 차종 통계·순위 |

## 4. 주요 사용 시나리오

### 시나리오 A. 출퇴근 직장인: "연료가 부족할 때, 가는 길에 주유하고 자동 기록"

- **누가**: 30대 직장인. 차계부 앱을 깔았다가 한 달 만에 그만둔 경험이 있다.
- **상황**: 퇴근길, 남은 주행거리가 50km 아래로 떨어졌다.
- **흐름**
  1. 주행 중 카드 한 장이 뜬다. "남은 주행거리 48km. 경로 위 최저가 주유소에 들를까요?" [들르기] [나중에]
  2. [들르기]를 누르면 주유소가 내비 경유지로 들어간다.
  3. 주유 후 출발하면 차곡이 주유를 감지한다. "42.3L, 약 7만 1천 원(오피넷 단가 기준). 기록할까요?" [확인]
  4. 월말에 지출, 주행 모드별 연비, 같은 차종 평균과의 비교가 자동으로 정리된다.
- **사용 API**: Vehicle(연료 %, 주유 후 거리, 총 주행거리, 연비, 주행 모드), NaviHelper(경유지 추가, 현재 위치), 오피넷

### 시나리오 B. 정비소 방문: "다녀오기만 하면 기록이 남는다"

- **누가**: 40대 운전자. 엔진오일 교체 시기를 늘 놓친다.
- **상황**: 차곡이 엔진오일 교체 주기 도달과 엔진오일 레벨 경고를 함께 알렸다.
- **흐름**
  1. 정차 중 "엔진오일 교체 시기입니다" 카드에서 [가까운 블루핸즈]를 누른다. 예약 페이지가 열리고, 정비소가 내비 목적지로 설정된다.
  2. 정비소에 도착하면 차곡이 도착을 기억한다.
  3. 정비 후 다시 시동을 걸면 "엔진오일을 교체하셨나요?" [교체함] [다른 정비] [안 함]
  4. [교체함] 한 번으로 정비 기록과 다음 교체 시점이 갱신된다.
- **사용 API**: Vehicle(엔진오일 레벨, 총 주행거리), NaviHelper(목적지 설정, 목적지 정보, 도착 이벤트)

### 시나리오 C. 사고 순간: "경황이 없어도 다음 할 일이 보인다"

- **누가**: 운전 경력 2년 차 운전자.
- **상황**: 교차로에서 추돌 사고가 나 에어백이 터졌다.
- **흐름**
  1. 차곡이 에어백 전개를 감지하고 화면에 사고 대응 카드를 띄운다. "보험사 긴급출동: ○○손해보험 1588-XXXX"
  2. 2차 사고 예방(비상등, 안전한 곳으로 대피), 사진 촬영 등 대응 순서를 큰 글자로 보여 준다.
  3. 사고 시각과 위치, 주행거리가 차계부에 사고 기록으로 남는다.
- **사용 API**: Vehicle(에어백 전개, 총 주행거리), NaviHelper(현재 위치)

## 5. 개발 계획

### 5.1 Pleos Connect 환경에서의 구현 방법

```
차량 (Pleos Connect, AAOS)
  차곡 앱 (Kotlin, Jetpack Compose, MVI)
    ├─ Vehicle SDK      총 주행거리·연료·연비·주행 모드·에어백·안전 경고·VIN
    ├─ NaviHelper SDK   목적지·경유지 설정, 경로·도착 이벤트, 현재 위치, 제한속도
    ├─ Gleo AI 앱 연동   음성 기록 함수 호출 (조건부)
    ├─ AAOS Car API     차속, 시동, 남은 주행거리 (표준 데이터는 표준 API 우선)
    └─ Room DB          기록 저장. 오프라인에서도 핵심 기능 동작
          │ HTTPS (동의한 경우만, 가명화한 요약값)
백엔드 (NestJS, PostgreSQL, Redis)
    차종별 통계·순위, 스킨 마켓·커뮤니티, 오피넷 유가·주유소 캐시
```

- **주행 안전**: 주행 중에는 `CarUxRestrictions`를 따라 경고·경유지 카드만 보여 준다. 키보드 입력은 정차 중에만 받는다.
- **차종 호환**: 모델명으로 분기하지 않고 `checkXxxCapabilities`로 지원 여부를 확인한다. 지원하지 않는 기능은 숨긴다.
- **리소스**: 상시 백그라운드 수집 대신 앱 실행·시동 시점의 스냅샷 비교로 기록한다. 주행 중 CPU 5% 미만, RAM 400MB 이하를 지킨다.
- **개인정보**: 차량 데이터는 기기 안에 저장한다. 서버로는 동의한 사용자의 가명화한 요약값(차종, 월 평균 연비)만 보낸다. 주행 데이터는 마케팅에 쓰지 않는다. 대여 모드에서는 개인 기록을 숨긴다.

### 5.2 UI 설계 원칙

Pleos Connect UI 디자인 가이드를 따른다.

- 모든 화면을 Portrait(1창)와 Landscape(2창) 두 레이아웃으로 만든다. Landscape에서는 기록 목록과 상세를 나란히 보여 준다.
- Light·Dark 테마를 모두 지원하고, 색은 Pleos 디자인 토큰만 쓴다.
- 버튼, 팝업, 토스트, 탭은 Pleos 컴포넌트를 쓴다. 본문은 최소 26 크기로, 핵심 정보는 1~2초 안에 읽히게 한다.
- 주행 중 카드는 정보 한 줄과 버튼 두 개로 제한하고, 장식 애니메이션을 쓰지 않는다.

### 5.3 SDK / API 사용 계획

| SDK / API | 사용 기능 | 쓰는 곳 | 상태 |
|---|---|---|---|
| Vehicle - Odometer | 총 주행거리(km), 이번 주행·주유 후 거리 | 주행거리 자동 기록, 주유 감지, 대여 모드 | 사용 가능 |
| Vehicle - Fuel | 연료 %, 누적·주유 후·순간 연비 | 주유 감지, 모드별·경로별 연비, 남은 주행거리 계산 | 사용 가능 |
| Vehicle - DrivingMode | 주행 모드 | 모드별 연비 | 사용 가능 |
| Vehicle - Safety, Tire | 에어백 전개, 엔진 이상, 오일류 레벨, 워셔액, 타이어 저압 | 사고 대응, 정비 권유 | 사용 가능 |

| AAOS Car API | 차속, 시동, 남은 주행거리 | 운전 점수, 재시동 감지, 주유소 안내 | 플랫폼 표준 |

핵심 플로우(자동 기록, 주유소 경유, 정비소 방문 기록, 사고 대응, 정비 권유)는 모두 **현재 사용 가능한** Vehicle·NaviHelper SDK로 동작한다. 준비 중이거나 목록 밖의 SDK는 음성 기록에만 쓰고, 안 되면 Android 표준 음성인식으로 대체한다.

## 6. 기대효과와 발전 가능성

### 6.1 타깃 고객

| 구분 | 고객 | 핵심 가치 |
|---|---|---|
| 1차 | Pleos Connect 탑재 차량의 개인 운전자, 특히 차 관리를 하고 싶지만 기록을 귀찮아하는 30~40대 | 입력 없는 차계부, 주유·정비 연결 |
| 2차 | 같은 차종 커뮤니티 활동을 즐기는 운전자 | 통계·순위, 꾸미기·스킨 |
| 3차 | 차를 빌려주거나 공유하는 운전자, 업무용 차량 운전자 | 대여 모드, 경로별 운행 기록 |

### 6.2 예상 MAU와 Retention `[근거 필요]`

- **MAU 산식**: Pleos Connect 탑재 차량 수 `[근거 필요]` × 앱 설치율 `[가정]` × 월 1회 이상 실행률 `[가정]`
- **Retention이 높은 이유**
  - 사용자가 아무것도 하지 않아도 기록이 쌓인다. 모바일 차계부의 이탈 원인인 "입력 피로"가 구조적으로 없다.
  - 주유(평균 1~2주 주기)와 정비 같은 반복 이벤트가 앱을 다시 열게 만든다.
  - 같은 차종 순위와 스킨 커뮤니티가 기록 외의 재방문 동기를 만든다.
  - 목표: 30일 Retention `[근거 필요: 공개된 차량 관리·차계부 앱의 Retention 수치와 비교]`

### 6.3 확대 계획

1. **빌트인캠 연동**: 차량 블랙박스 API가 공개되면 사고 감지 시 영상 기록을 사고 기록에 붙인다.
2. **정비 예약 직접 연동**: 오토큐·블루핸즈 예약 시스템과 연동해 앱 안에서 예약을 끝낸다.
3. **보험 연계**: 차량이 기록한 실제 주행거리로 마일리지 특약 할인을 쉽게 받게 한다(사용자 동의 기반).
4. **법인 차량 관리(B2B)**: 경로별 운행 기록을 법인 운행일지와 비용 정산으로 확장한다.
5. **전기차 확장**: 같은 구조로 충전 기록(배터리 %, 전비)과 충전소 경유지를 지원한다.
