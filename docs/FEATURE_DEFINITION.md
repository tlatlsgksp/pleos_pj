## 3. 데이터 출처 원칙

- 커뮤니티에 올라가는 숫자는 차가 만든 값만 쓴다. 출처 표시를 항상 붙인다.
- 위치는 그룹 드라이브 중(C3)과 핀할 때(D1)만 서버로 간다.
- 서버가 없을 때(1차 시연)는 커뮤니티 데이터를 "시연용"으로 표시한 내장 데이터로 보여 준다.

## 5. 상세: 함께 달리는 멤버 실시간 위치 (C3)

워키토키를 쓰는 그룹 드라이브 멤버들의 위치를 서로 실시간으로 보여 준다. 위치는 **상황에 따라 차(Pleos)에서도, 폰 앱에서도** 받는다. 한 멤버의 위치는 서버에서 하나로 합쳐 보여 준다.

### 5.1 위치 출처

| 출처 | 받는 값 | 권한 | 쓰는 상황 | 상태 |
|---|---|---|---|---|
| ① 차: NaviHelper `onCurrentLocationInfo` | 위도·경도, 진행 방향, 주소, **경로 정보(남은 거리 등)** | `NAVI_ROUTE` | 차에서 경로 안내 중. 그룹 드라이브 목적지가 내비에 들어가 있으므로 기본 경로 | 바로 사용 가능. 경로 안내가 없을 때도 오는지는 에뮬레이터에서 확인 필요 |
| ② 차: FusedLocation SDK | 위도·경도, 고도, 진행 방향 | `FUSED_LOCATION` (런타임 요청) | 경로 안내가 없어 ①이 안 올 때 | 문서상 준비 중이나 의존성은 받아짐. 공모전에는 미공개 SDK도 제공 |
| ③ 폰: Android 위치 | 위도·경도, 진행 방향, 속도 | 폰 위치 권한 | 차 없이 참여하는 멤버(동승자, Pleos가 아닌 차), 차 신호가 끊겼을 때 | 폰 앱에서 구현 |
| 속도 | 차량 속도 | AAOS `PERF_VEHICLE_SPEED` | ①②에는 속도가 없어 차에서 따로 읽음 | 사용 가능(실측) |

**고르는 순서 (멤버 한 명 기준)**: 차 ① → 차 ② → 폰 ③. 위에서부터 최근 값(15초 이내)이 있는 출처를 쓴다. 출처가 바뀌어도 화면의 멤버는 그대로 하나다.

### 5.2 흐름

```
멤버의 차 (①/② + 차속)  ─┐
                          ├─▶ 서버: 그룹 채널(WebSocket) ─▶ 다른 멤버의 차·폰
멤버의 폰 (③)          ─┘     · 멤버마다 최신 위치 1개만 보관 (메모리, 30초 지나면 삭제)
                               · 그룹 드라이브가 끝나면 모두 삭제, 기록으로 남기지 않음
```

- 보내는 값: 멤버 ID, 위도·경도, 진행 방향, 속도, 출처, 목적지까지 남은 거리(①일 때), 시각.
- 보내는 주기: 움직이는 중 3초마다 또는 20 m 이동 시. 서 있으면 15초마다.
- 신호 상태: 15초 넘게 새 값이 없으면 흐리게 "신호 약함", 1분이 넘으면 "마지막 위치 n분 전"으로 바꾼다.

### 5.3 화면

| 위치 | 보여 주는 것 |
|---|---|
| 차 (주행 중) | 앱 안의 지도에 멤버 위치(꾸민 차 아이콘)와 진행 방향. 무전기 앱처럼 멤버 프로필(꾸민 차 사진)을 한 줄로 띄우고, 지금 말하는 멤버의 프로필이 커지고 밝아진다. 거리 문구는 쓰지 않는다. 주행 중에는 지도를 만지지 않아도 되게 내 차와 멤버가 모두 들어오도록 자동으로 맞춘다 |
| 차 (정차 중) | 지도 확대·이동, 멤버를 눌러 [친구에게 가기] |
| 폰 | 지도 위 멤버 위치(꾸민 차 아이콘), 진행 방향, 말하는 멤버 강조 |

### 5.4 결정 (2026-11-15)

| 항목 | 결정 |
|---|---|
| 차와 폰이 둘 다 있는 멤버 | 차 우선. 차 신호가 15초 끊기면 폰 |
| 차 화면 표시 | 앱 안에 지도. **네이버 지도 SDK**를 차량 앱과 폰 앱에 쓴다 |
| 공유 기간 | 그룹 드라이브 동안 자동. 참여하면 시작, 도착하거나 나가면 끝. 참여 화면에 "위치를 공유해요"를 보여 준다 |
| 폰만 있는 멤버 | 허용. 동승자, Pleos가 아닌 차를 타는 친구도 폰으로 위치와 워키토키에 참여한다 |

### 5.5 확인할 것 (에뮬레이터)

- 경로 안내가 없을 때 NaviHelper 위치 이벤트가 오는지, 오는 주기
- FusedLocation 런타임 권한 창이 Pleos에서 뜨는지
- 위치 갱신 주기가 3초보다 느리면 보내는 주기를 맞춘다
- 네이버 지도 SDK가 Pleos(AAOS, 2560×1440 160dpi)에서 그려지는지, 클라이언트 키 발급, 오프라인일 때의 동작
- Mobility Services 카테고리에서 주행 중 앱 안 지도 표시가 허용되는지. 막히면 주행 중에는 거리 목록, 정차 중에만 지도로 바꾼다

## 6. 상세: 앱 지도에 내 내비 경로 그리기

Pleos 내비에 찍은 경로를 우리 앱 지도(네이버 지도)에 그리고, 경로 위에 있는 제보·핀·주유소·충전소를 골라 보여 준다.

### 6.1 NaviHelper로 받을 수 있는 것 (SDK 3.0.5, 클래스 직접 확인)

| 받는 값 | 어디서 | 쓰는 곳 |
|---|---|---|
| 출발지·경유지·목적지 좌표와 경로상 위치(0~1) | `TripSummary.routePoints` (`RoutePointInfo`: 위도·경도, `ratioOnRoute`, ORIGIN/WAYPOINT/DESTINATION, 충전소 여부) | 경로를 다시 그릴 기준점 |
| 목적지·경유지 좌표, 남은 거리·시간 | `onDestinationInfo`, `onWayPointInfo` | 같음 |
| 지금 위치, 진행 방향, 경로 ID | `onCurrentLocationInfo` (`routeId`, `currentRouteIndex`) | 경로가 바뀌었는지 판단 |
| 구간별 정체 (경로상 시작·끝 비율) | `TripSummary.trafficConditions` | 경로 선 색 |
| 교통 사건 좌표 (사고, 도로 파손, 공사, 행사, 재난) | `RouteStateInfo.trafficStatus.trafficEventList` | **공식 교통 정보**로 우리 제보와 같은 지도에 표시 |
| 앞의 단속카메라·주의 구간까지 남은 거리 | `onCameraAlert`, `onCautionPointInfo` | 참고(Pleos 내비가 이미 안내함) |

**받을 수 없는 것: 경로 선 자체(도로를 따라가는 좌표 목록).** 그래서 경로 선은 아래처럼 다시 만든다.

### 6.2 경로 선 만들기

1. NaviHelper에서 출발지·경유지·목적지 좌표를 받는다.
2. 같은 좌표로 **네이버 길찾기 API**(Directions)를 불러 경로 선을 받는다.
3. 그 선을 네이버 지도에 그리고, 선에서 일정 거리(예: 200 m) 안에 있는 제보·핀·주유소·충전소를 "경로 위"로 본다. 홈의 [제보] 카드 숫자와 경로 위 제보 배너도 이 판단을 쓴다.
4. 재탐색(`onReRouteEnded`)이나 경유지 변경 이벤트가 오면 2번을 다시 한다.

Pleos 내비와 네이버가 다른 도로를 고를 수 있다. 지금 위치가 우리 선에서 벗어나면 다시 불러 맞춘다.

### 6.3 확인할 것 (에뮬레이터)

- `TripSummary`가 지금 안내 중인 경로에 대해 오는지(`onTripInfo`를 받으려면 `requestTrip`이 필요한지)
- `trafficEventList`가 실제로 채워져 오는지
- 네이버 길찾기 API 키 발급과 호출 한도
