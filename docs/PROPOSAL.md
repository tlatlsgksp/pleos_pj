# 차곡: 차가 직접 쓰는 차계부

접수양식 02장 "앱 프로젝트 소개" 제출용 원고다. 작업 메모와 근거는 [기획서 초안](PROPOSAL_DRAFT.md)과 [기획 기반 정리](PLANNING_FOUNDATION.md)에 두고, 이 문서는 심사위원이 읽을 문장만 담는다.

- 작성일: 2026-10-28 (v1.0)
- 블라인드 심사: 성명, 연락처, 소속, 회사명, 기존 서비스명을 쓰지 않는다.
- `[ ]`로 표시한 곳은 팀이 정하거나 채워야 하는 곳이다. 맨 끝 "제출 전 확인"에 모았다.
- **실측**은 Pleos Connect 에뮬레이터에서 시험 앱으로 직접 확인했다는 뜻이다.

## 1. 앱 한 줄 소개

> **차가 직접 쓰는 차계부.** 주행거리와 연료·배터리 사용량을 차량이 기록하고, 소모품 교체 시점을 스스로 맞추고, 필요한 주유소·충전소·정비소를 가는 길에 내비 경유지로 넣어 준다. 쌓인 기록은 차량이 보증하는 **관리 이력서**가 된다. 연료차와 전기차를 모두 지원한다.

## 2. 기획 배경

### 2.1 고객 니즈: 차 관리는 하고 싶지만 기록은 귀찮다

| 불편한 순간 | 지금 하는 일 | 결과 |
|---|---|---|
| 주유·충전을 마쳤을 때 | 영수증을 보고 금액·양·주행거리를 폰에 입력한다 | 몇 번 하다 그만둔다. 연비와 지출 통계가 틀어진다 |
| 정비소에 다녀왔을 때 | 정비 내역을 따로 입력해야 한다 | 대부분 남기지 않는다. 다음 교체 시점을 모른다 |
| 연료·배터리가 얼마 안 남았을 때 | 운전 중에 주유소를 찾아 내비를 다시 설정한다 | 주행 중 조작이 위험하고, 반대편이나 비싼 주유소에 들른다 |
| 차를 팔 때 | 정비 영수증을 뒤지거나 "관리 잘했어요"라고 말로만 한다 | 잘 관리한 차도 그만큼 값을 인정받지 못한다 |
| 내 차 연비가 좋은 편인지 궁금할 때 | 비교할 기준이 없다 | 운전 습관을 바꿀 동기가 없다 |

모바일 차계부 앱은 차의 주행거리를 알 수 없다. 그래서 **사용자에게 주기적으로 주행거리 입력을 요청해야만** 정비 주기를 계산할 수 있고, 입력이 끊기는 순간 모든 계산이 틀어진다. `[근거: 공개 자료의 차계부 앱 지속 사용률 수치]`

### 2.2 왜 차 안이어야 하는가

모바일 차계부의 한계는 데이터가 사람 손을 거친다는 점이다. 차량 앱은 다르다.

- 총 주행거리, 배터리 에너지, 연료 잔량, 실측 연비를 **차가 알고 있다.** 에뮬레이터에서 총 주행거리를 바꾸면 앱이 바로 받는다(실측).
- 엔진 이상, 오일류·타이어 경고를 **차가 먼저 안다.**
- 어디로 가는지, 언제 도착했는지를 **차량 내비가 안다.** 앱이 내비에 경유지를 넣으면 운전자 확인 없이 바로 경로에 들어간다(실측).

차곡은 이 데이터로 **기록을 없애고**, 정비·주유가 필요한 순간을 **이동 경로와 연결하고**, 쌓인 기록을 **차의 가치로 바꾼다.**

## 3. 주요 기능 및 차량 특화 요소

### 3.1 기능 구성

**A. 자동 기록: 입력이 없는 차계부**

| 기능 | 하는 일 | 차량 특화 요소 |
|---|---|---|
| 주행거리 자동 기록 | 시동이 걸리면 총 주행거리를 읽어 기록한다. 앱이 꺼져 있던 기간의 주행도 총 주행거리 차이로 이어 붙인다 | Vehicle SDK 총 주행거리(실측), 부팅 시 백그라운드 서비스(실측) |
| 관리항목 주기 자동 갱신 | 엔진오일·필터·타이어·브레이크 등 소모품마다 마지막 교체 이후 주행거리와 기간으로 진행률을 계산한다. 주행거리가 실시간으로 들어오므로 진행률과 교체 알림이 늘 맞다. 연료차와 전기차는 관리항목이 다르다 | Vehicle SDK 총 주행거리 구독 |
| 주유·충전 자동 감지 | 연료차는 주유 후 거리 초기화와 연료 증가로, 전기차는 충전구 열림과 배터리 증가로 감지한다. 위치로 주유소·충전소를 찾고 단가로 금액을 미리 채운다. 운전자는 확인만 누른다 | Vehicle SDK 연료·충전구·배터리(실측), NaviHelper 현재 위치(실측), 오피넷·충전소 공공 API |
| 연비·전비 기록 | 연료차는 차량 측정 연비를, 전기차는 "주행거리 증가 ÷ 배터리 에너지 감소"를 쓴다. 정차 중 사용량을 공회전으로 분리해 **주행 효율**과 **전체 효율**을 나눠 보여 준다 | Vehicle SDK 연비·배터리 에너지, 차속·기어·브레이크(실측) |
| 효율 원인 분석 | 주행 중 에어컨 사용, 제동 빈도, 급가속, 정체 구간을 함께 저장해 "에어컨을 켠 구간 전비가 12% 낮아요", "정체 18분 때문에 이번 주행 전비가 9% 떨어졌어요"처럼 원인과 방법을 알려 준다 | Vehicle SDK 공조·브레이크(실측), AAOS 차속, NaviHelper 정체 구간(실측) |
| 운행 기록·통행료 | 목적지마다 거리·시간·통행료·효율을 기록한다. 업무용 운행일지로 그대로 쓸 수 있다 | NaviHelper 경로 시작(예상 통행료)·도착 이벤트(실측) |
| 음성 기록 | "엔진오일 교체 8만 원 기록해 줘"처럼 말로 기록한다 | Gleo 앱 함수 호출(등록 가능 여부 확인 중). 대체 경로: 앱 마이크(실측) + 음성인식 |

**B. 가는 길에 끝내는 차 관리**

| 기능 | 하는 일 | 차량 특화 요소 |
|---|---|---|
| 진행 방향 기준 주유소·충전소 경유 | 남은 주행거리가 기준 아래로 떨어지면 후보마다 "들렀다 가면 몇 분 더 걸리는지"를 계산해 추가 시간과 가격 순으로 고른다. 반대 차선이나 유턴이 필요한 곳은 추가 시간이 커서 자연히 뒤로 밀린다. 고르면 내비 경유지로 넣고, 전기차는 "경유지 도착 시 예상 배터리"도 보여 준다 | NaviHelper 경유지 추가·현재 위치와 진행 방향·도착 예상 잔여 에너지(실측), 길찾기 API |
| 정비소 경유 제안 | 교체 시기가 다가온 항목이 있으면, 평소 다니는 길이나 오늘 목적지 근처의 정비소를 "들르면 몇 분 더"와 함께 제안한다. 따로 시간을 내서 정비소에 가는 대신 가는 길에 끝낸다 | NaviHelper 목적지 정보·경유지 추가 |
| 정비소 방문 자동 기록 | 내비 목적지가 정비소였으면 도착을 기억했다가, 다음 출발 때 "어떤 정비를 받으셨나요?"를 묻는다. 버튼 한 번으로 기록과 다음 교체 시점이 갱신된다 | NaviHelper 도착 이벤트, 주행 시작 감지(기어·주행거리) |
| 시동 브리핑 | 차에 타면 오늘 챙길 것을 한 장으로 보여 준다. "엔진오일 92%, 오늘 경로 근처에 정비소가 있어요", "배터리 34%, 목적지까지는 충분해요" | 부팅 신호 + 총 주행거리·배터리·관리항목 진행률. 화면 자동 실행은 막혀 있어 알림으로 연다(실측) |

**C. 기록이 가치가 되는 순간**

### 3.2 주행 중과 정차 중

앱 카테고리는 **Mobility Services**다. 카테고리 정책이 주행 중 허용 예로 드는 "주행과 관련된 차량 관리", "주유소 탐색"에 맞춰 주행 중에는 최소한의 기능만 연다.

| 상황 | 쓸 수 있는 기능 | 방식 |
|---|---|---|
| 주행 중 | 주유소·충전소·정비소 경유 제안, 경고·사고 알림, 워키토키 `[ ]` | 정보 한 줄과 버튼 두 개("들르기 / 나중에")인 카드 한 장. 키보드 입력 없음 |
| 시동 직후·주행 시작 직후 | 시동 브리핑, 주유·충전·정비 기록 확인 | 버튼 한 번 |
| 정차 중 | 기록 수정, 관리 이력서, 주행 다시보기, 통계, 순위, 설정 | 전체 화면 |

### 3.3 차별점

| | 모바일 차계부 | 차곡 |
|---|---|---|
| 주행거리 | 직접 입력 | 차가 기록 |
| 소모품 교체 시점 | 입력이 밀리면 틀어짐 | 늘 맞음 |
| 주유·충전 기록 | 영수증 보고 입력 | 감지 후 확인만 |
| 연비·전비 | 입력값으로 계산, 공회전 섞임 | 차량 신호로 계산, 공회전 분리, 원인 분석 |
| 주유소·충전소·정비소 | 앱에서 검색 후 내비 재설정 | 진행 방향 기준으로 골라 내비 경유지로 바로 추가 |
| 기록의 신뢰도 | 사람이 쓴 메모 | 차량 값이 찍힌 관리 이력서 |

## 4. 주요 사용 시나리오

### 시나리오 A. 퇴근길 충전: "가는 길에 충전하고, 기록은 저절로"

- **누가**: 30대 직장인, 전기차 운전자. 차계부 앱을 깔았다가 한 달 만에 그만둔 적이 있다.
- **흐름**
  1. 내비로 집에 가는 중, 남은 주행거리가 기준 아래로 떨어지자 카드가 뜬다. "충전소 들르면 4분 더 걸려요. 도착 시 배터리 18% 예상." [들르기] [나중에]
  2. [들르기]를 누르면 진행 방향 오른쪽 충전소가 내비 경유지로 들어간다.
  3. 충전구가 열리고 배터리가 오르면 차곡이 충전을 감지한다. "32kWh, 약 1만 1천 원. 기록할까요?" [확인]
  4. 월말에 지출, 공회전을 뺀 주행 전비, 같은 차종 평균과의 비교, 전비를 떨어뜨린 원인(에어컨, 정체 구간)이 정리된다.
- **사용 API**: Vehicle(총 주행거리, 배터리 에너지·잔량, 충전구), NaviHelper(경유지 추가, 현재 위치·진행 방향, 도착 예상 잔여 에너지), 길찾기·충전소 API
- 연료차도 같은 흐름이다. 주유소와 오피넷 단가를 쓴다.

### 시나리오 B. 정비: "따로 시간 내지 않고, 다녀오면 기록이 남는다"

- **누가**: 40대 운전자. 엔진오일 교체 시기를 늘 놓친다.
- **흐름**
  1. 아침에 시동을 걸자 시동 브리핑이 뜬다. "엔진오일 교체 시기예요. 오늘 목적지 근처 정비소, 들르면 6분 더."
  2. [경유지로 추가]를 누르면 정비소가 경로에 들어간다.

## 5. 개발 계획

### 5.1 Pleos Connect 환경에서의 구현 방법

```
차량 (Pleos Connect, AAOS)
  차곡 앱 (Kotlin, Jetpack Compose, MVI)
    ├─ Vehicle SDK      총 주행거리·배터리·연료·연비·공조·브레이크·기어·안전 경고·VIN
    ├─ NaviHelper SDK   목적지·경유지 설정, 경로 시작·도착 이벤트, 정체 구간, 현재 위치·진행 방향
    ├─ Gleo 앱 연동      음성 기록 함수 호출 (조건부)
    ├─ AAOS Car API     차속, 오디오 포커스
    ├─ 기록 서비스        부팅 시 시작, 주행거리·에너지 스냅샷
    ├─ 지도 SDK          주행 다시보기
    └─ Room DB          기록 저장. 오프라인에서도 핵심 기능 동작
          │ HTTPS (동의한 경우만, 가명화한 요약값)
백엔드 (NestJS, PostgreSQL, Redis)
    차종별 통계·순위, 관리 이력서 공유 링크, 워키토키 음성 중계,
    유가·주유소·충전소 캐시, 길찾기·지오코딩 호출
```

- **연료차·전기차**: 에너지 종류를 처음부터 데이터 구조에 넣는다. 주유와 충전은 "에너지 기록" 하나로 묶고, 감지 방식·효율 계산·관리항목 목록·주유소와 충전소만 나눈다.
- **기록 시점**: 부팅 시 백그라운드 서비스가 주행거리·에너지 스냅샷을 찍는다(실측). 화면은 자동으로 띄울 수 없어(실측) 알림으로 연다. 앱이 꺼져 있던 동안은 누적값 차이로 합계를 복원한다. 위치·운전 습관처럼 촘촘한 수집은 앱을 띄워 둔 주행에서만 한다.
- **관리 이력서 신뢰도**: 정비 기록을 저장할 때 차량에서 읽은 총 주행거리·VIN·시각을 함께 묶어 서명한다. 사용자가 금액·메모는 고칠 수 있지만 차량 값은 고칠 수 없고, 고친 기록은 표시가 남는다.
- **주행 안전**: 주행 중에는 `CarUxRestrictions`를 따라 경고·경유지 카드만 보여 준다.
- **차종 호환**: 모델명으로 분기하지 않고 지원 여부 확인 함수(`checkXxxCapabilities`)로 판단해, 지원하지 않는 기능은 숨긴다.
- **리소스**: 주행 중 CPU 5% 미만, RAM 400MB 이하. 백그라운드에서는 스냅샷만 찍고 바로 끝낸다.
- **개인정보**: 차량 데이터와 위치는 기기 안에 저장한다. 서버로는 동의한 사용자의 가명화한 요약값(차종, 월 평균 효율)만 보낸다. 관리 이력서는 사용자가 공유할 때만 링크가 만들어지고, 위치·운행 경로는 넣지 않는다.

### 5.2 UI 설계 원칙

Pleos Connect UI 디자인 가이드를 따른다.

- 모든 화면을 Portrait(1창)와 Landscape(2창) 두 레이아웃으로 만든다. Landscape에서는 목록과 상세를 나란히 보여 준다.
- Light·Dark 테마를 모두 지원하고, 색은 Pleos 디자인 토큰만 쓴다. 버튼·팝업·토스트·탭은 Pleos 컴포넌트를 쓴다.
- 본문은 최소 26 크기, 핵심 정보는 1~2초 안에 읽히게 한다.
- 주행 중 카드는 정보 한 줄과 버튼 두 개로 제한하고 장식 애니메이션을 쓰지 않는다.

## 6. 기대효과와 발전 가능성

### 6.1 타깃 고객

| 구분 | 고객 | 핵심 가치 |
|---|---|---|

### 6.2 사용자 확보와 지속 이용

- **확보**: 차에 설치하는 것만으로 첫날부터 주행거리와 관리항목 진행률이 채워진다. 가입·입력 없이 가치를 먼저 보여 준다.
- **예상 MAU**: Pleos Connect 탑재 차량 수 `[ ]` × 설치율 `[ ]` × 월 1회 이상 실행률 `[ ]`
- **지속 이용이 높은 이유**
  - 사용자가 아무것도 하지 않아도 기록이 쌓인다. 모바일 차계부의 이탈 원인인 "입력 피로"가 구조적으로 없다.
  - 시동 브리핑, 주유·충전(1~2주 주기), 정비가 앱을 다시 열게 만든다.
  - 기록이 쌓일수록 관리 이력서의 가치가 커져, 차를 바꾸기 전까지 그만둘 이유가 줄어든다.
  - 같은 차종 순위와 워키토키 그룹이 기록 밖의 재방문 동기를 만든다.

### 6.3 사업성과 확대 계획

1. **관리 이력서 제휴**: 중고차 거래·인증 중고차 플랫폼에 차량이 보증하는 관리 이력을 제공한다. 잘 관리한 차의 가치를 높이고, 플랫폼은 신뢰할 수 있는 이력을 얻는다.
2. **정비 연계**: 가는 길 정비소 제안을 정비 네트워크 예약과 연결한다. 예약·방문 단위 제휴 수수료가 가능하다.
3. **보험 연계**: 차량이 기록한 실제 주행거리로 마일리지 특약을 쉽게 받게 한다(사용자 동의 기반).
4. **법인 차량 관리(B2B)**: 자동 운행일지, 비용 정산, 주행 다시보기를 묶어 법인용 구독으로 제공한다.
5. **Pleos API 개방과 함께 넓히기**: 개발하며 필요했지만 지금은 열려 있지 않은 기능(하이패스 거래, 시동 이벤트, 지난 주행 이력, 핸들 사용자 지정 키, 주행 화면 차량 테마 등)을 우회 방법과 안전 장치까지 붙여 제안서로 정리했다. 열리면 예상 통행료가 실제 결제 금액이 되고, 앱을 켜지 않은 날의 운행도 빠짐없이 남는다.
