Moli 화면 기초 규칙

2026-11-15 Moli로 이름을 바꾸며 되살린 문서다. 글자 크기·간격·카드·버튼 규칙은 그대로 따르고, 화면 예시(홈·차계부·내 차 탭)는 Moli 이전 구조 기준이다.

2026-11-15 초안 · 근거: docs/UI_DESIGN_GUIDE.md(Pleos 타이포·컴포넌트), 현재 코드 집계(ui/feature/*) · 짝 문서: ia-flow-layout.html, layout-variants.html

지금 앱은 Pleos 컴포넌트(버튼, 카드, 상단 바)는 있지만 "어떤 제목에 어떤 크기를, 묶음은 어떻게, 간격은 얼마"라는 규칙이 없어 화면마다 제각각이다. 같은 "목록"이 홈·차계부·내 차에서 세 가지 모양으로 그려지고, 카드 제목 크기가 3종, 간격 값이 9종 섞여 있다.

제안: 글자 역할 8개, 간격 6단계, 묶음 규칙 4개, 문구 규칙을 정하고, 코드에서는 역할 이름으로만 쓰게 해서(PleosText.sectionTitle 등) 화면이 규칙을 벗어날 수 없게 한다.

버튼"차계부에서 보기"(카드 머리, Small) · "꾸미러 가기"(Filled) · "확인하기"(Filled) · 설정 −/+ (Small)"더 보기" 성격의 이동이 일반 버튼 모양. 가이드의 Text button(파란 글자 + ›)을 안 씀.

색배터리 부족 제안 카드 전체가 빨강(negative), 기록 준비 라벨 파랑(positive), 관리 양호 초록(active)"위험"이 아닌 제안에 위험색 배경. 의미색 쓰임 기준이 없다.

5. 묶음 규칙

#규칙이유
1섹션 = 섹션 제목(카드 밖) + 내용. 열마다 섹션이 1~3개."무엇에 관한 묶음인가"를 한 가지 방식으로 보여 준다.
2카드 안에 카드를 넣지 않는다. 여러 항목은 목록 카드 하나 안의 행(구분선)으로.경계가 이중으로 보이지 않고, 홈·차계부·내 차의 목록이 같은 모양이 된다.
3카드 종류는 4개만: 정보 카드(흰색) · 목록 카드(흰색 + 행) · 행동 카드(흰색 + Filled 버튼 1개) · 위험 카드(빨강, 사고처럼 즉시 위험할 때만).배터리 부족 "제안"은 행동 카드 + 빨간 status. 빨간 배경은 정말 위험할 때를 위해 아낀다.
4Filled 버튼은 카드당 최대 1개, 화면에서 가장 중요한 행동에만. 카드 버튼은 Medium, 섹션 제목 옆은 Text button.주행 중 무엇을 눌러야 하는지 한눈에.

7. 개선 방법 (코드)

순서할 일효과
1ui/design에 규칙을 코드로: PleosText(역할 8개), Space(6단계), SectionHeader(title, action), ListCard + ListRow, TextButton, ActionCard화면은 역할 이름만 고르면 된다
2화면에서 MaterialTheme.typography.*, 숫자 .dp, "%.1f km" 직접 쓰기를 없앤다 (지금 41곳 / 30여 곳 / 4곳)규칙 밖의 값이 생기지 않는다
3코드 리뷰 체크 대신 테스트로 막기: ui/feature 소스에 위 패턴이 있으면 실패하는 단위 테스트 하나나중에 들어오는 화면도 자동으로 지킨다
4홈 → 차계부 → 내 차 순서로 바꾸고, 각 화면을 2칸(1700×1184, 1274×855)·1칸(840×1184, 628×855) 미리보기로 확인layout-variants.html의 시안과 같이 진행 가능
5docs/UI_DESIGN_GUIDE.md에 이 문서의 2~5절을 "우리 앱 규칙" 절로 옮겨 적는다디자이너·개발자가 같은 기준을 본다

미리 정할 것: ① 상태 값을 48로 키울지(주행 중 가독성 ↑, 2칸 왼쪽 열 폭은 충분), ② 목록을 "카드 하나 + 행"으로 통일할지(지금 설정 행은 카드마다 분리), ③ 단위 띄어쓰기 "12,370 km" 확정.
