기획서(접수양식) 작성 전에 알아야 할 전제, 모바일 차계부의 한계 중 Pleos API로 정확도를 높일 수 있는 지점, 내비게이션 연동 범위를 정리한다.

- 작성일: 2026-10-25
- 근거
  - 플랫폼·공모전: [Pleos 조사 노트](PLEOS_PLATFORM_RESEARCH.md), [설계 원칙](APP_DESIGN_PRINCIPLES.md), [설계 가이드](APP_DESIGN_GUIDE.md)
  - 모바일 차계부: 시중 차계부 앱의 공개된 기능 설명과 제조사 정비 매뉴얼
  - 내비: NaviHelper 3.0.5 가이드, Dokka 클래스 문서, [샘플 앱](https://github.com/Pleos-Playground/pleos-sample-navi-app)
- 표시는 조사 노트와 같다. ✅ 원문 확인, 🟡 추론, ❓ 미확인, ⚠️ 출처 충돌.

## 2. 모바일 차계부의 한계와 Pleos로 정확해지는 것

모바일 차계부의 차량 데이터는 **전부 사람이 입력한다.** 주행거리는 직접 입력, 차계부 기록, 정비 내역, 외부 차계부 가져오기 같은 경로로만 들어오고, 그래서 앱들이 주기적으로 입력 알림을 보낸다. Pleos에서는 이 값을 차량에서 직접 읽을 수 있다. 이것이 "모바일 대비 차량만의 가치"(차량특화성)의 핵심 논거다.

### 2.1 기능별 비교

| 기능 | 모바일 차계부 방식 | Pleos에서 바뀌는 점 | 근거 API | 상태 |
|---|---|---|---|---|
| 현재 주행거리 | 직접 입력, 매일 알림 | 차량 값을 자동으로 읽는다. 입력 알림이 필요 없다 | Vehicle `getCurrentDistanceDriven`(km) / AAOS `PERF_ODOMETER` | ✅ API 의미 / ❓ 콘솔 목록에 없음, §2.2 |
| 소모품 교체 진행률 | (현재 km − 마지막 교체 km) ÷ 주기. 현재 km가 수동이라 늦고 부정확하다 | 현재 km가 자동이라 진행률이 실시간으로 맞는다. 알림 시점도 정확해진다 | 위와 같음 | 🟡 |
| 주유 기록 | 금액·주유량·단가·주행거리·위치를 모두 입력 | 주유를 감지해 주유량·주행거리·위치를 채운 초안을 만든다. 사용자는 금액만 확인한다 | `getTripSinceRefillDrivingDistance` 초기화 + `getFuelPercent` 상승, 위치는 NaviHelper `getCurrentLocationInfo` | ✅ API / 🟡 리셋 동작 미검증 |
| 주유량 계산 | 입력값 | 연료 % 변화 × 탱크 용량. 탱크 용량은 AAOS `INFO_FUEL_CAPACITY`, 없으면 공개 제원 자료나 사용자 입력 | `getFuelPercent` | 🟡 용량 출처 미정 |
| 평균 연비 | 주행거리 ÷ 주유량으로 계산. 주유를 빠뜨리면 틀린다 | 차량이 측정한 연비를 그대로 쓴다. 누적, 주유 이후, 순간 연비를 구분한다 | `getCumulativeFuelEconomy`, `getSinceChargeFuelEconomy`, `getInstantaneousFuelEconomy` | ✅ 단위는 L/100km라 km/L로 바꿔 보여 준다 |
| 엔진오일·브레이크액·미션오일·워셔액 | 주행거리·기간으로 추정만 한다 | 차량 센서의 레벨 경고를 함께 본다. "주기상 아직이지만 차량이 부족하다고 함"을 잡는다 | `getEngineOilLevelState`, `getBrakeFluidLevelState`, `getTransmissionOilLevelState`, `hasLowWasherFluidWarning` | ✅ |
| 타이어 | 50,000km / 60개월 주기 | 저압 경고를 실시간으로 받는다. 공기압 수치는 없다 | `getLowTirePressure` | ✅ |
| 엔진 이상 | 없음 | 경고등이 켜지면 정비소 경유지를 제안한다 | `hasPowerDownWarningIndicator` | ✅ |
| 사고 | 없음 | 에어백이 전개되면 보험사 연락을 권한다. 충돌 감지는 없다 | `hasSeatAirbagBeenDeployed` | ✅ |
| 차량 등록 | 번호판과 소유자명을 입력해 외부 차량 조회 API를 부른다 | VIN을 차량에서 읽어 입력 없이 등록한다. VIN → 차종 매칭은 따로 필요하다 | `getVINInfo` | ✅ API / 🟡 매칭 |
| 정비소 방문 기록 | 앱 안에서 예약한 건만 자동 기록 | 내비 도착 이벤트로 정비소 도착을 감지하고, 다음 시동 때 정비 내용을 묻는다 | NaviHelper `onDestinationArrived` + AAOS `IGNITION_STATE` | ✅ 내비 / 🟡 시동 |
| 운행 기록 | 없음 | 목적지마다 거리·시간·통행료가 자동으로 쌓인다. 업무용 운행일지로 확장할 수 있다 | `onRouteStarted`(tollFare), `onDestinationArrived`(distance, duration) | ✅ |
| 시내/고속 주기 구분 | 제조사 매뉴얼은 일반·가혹 조건 주기를 따로 두지만, 앱이 사용자 운전 패턴을 몰라서 못 쓴다 | 차속·주행모드를 샘플링해 시내·고속 비율을 구하고 교체 주기를 개인화한다 | AAOS `PERF_VEHICLE_SPEED`, `getCurrentDrivingModeState` | 🟡 |

### 2.2 주행거리 API 주의점 ❓

차계부의 모든 계산이 "현재 주행거리"에 걸려 있다. Vehicle SDK 원문(2026-10-25 확인)의 Odometer 메서드 의미는 다음과 같다.

| 메서드 | 의미 | 단위 |
|---|---|---|
| `getCurrentDistanceDriven` | **차량 총 주행거리(odometer)** ✅ | km |
| `getTripCurrentDrivingDistance` / `Time` | 이번 주행(시동 후) 거리·시간 ✅ | m / 분 |
| `getTripCumulativeDrivingDistance` / `Time` | 누적 주행정보. **총 주행거리가 아니다** ✅. 사용자가 리셋하는 값으로 보인다 🟡 | m / 분 |
| `getTripSinceRefillDrivingDistance` / `Time` | 마지막 주유 이후 거리·시간 ✅ | m / 분 |

- 총 주행거리는 `getCurrentDistanceDriven`이 맞다. 다만 콘솔 "사용 가능" 목록에 없어서 같은 `CAR_DRIVE` 권한으로 호출되는지 확인해야 한다 ❓.
- SDK 바이너리 확인(2026-10-26, Nexus `ai.pleos.playground:Vehicle:2.3.2`를 javap로 확인): `Odometer`에 `getCurrentDistanceDriven`, 실시간 구독 `registerDistanceDriven`, 지원 여부 확인 `checkCurrentDistanceDrivenCapabilities`가 **실제로 들어 있다** ✅. 문서에서 숨겨진 `getRangeRemainingDistance`(남은 주행거리)와 `CarInfo.getCRNInfo`(차량 등록번호로 보임 🟡)도 있다. 권한 검사는 SDK가 아니라 차량 서비스 쪽에서 해서 바이너리로는 판단할 수 없다 ❓ → 에뮬레이터 호출로 확인한다.
- **에뮬레이터 실측(2026-10-26): `getCurrentDistanceDriven`이 `CAR_DRIVE` 권한으로 동작한다 ✅.** 콘솔에서 바꾼 값이 바로 들어온다. 다만 에뮬레이터 차량이 전기차 구성이라 연료 %·연비·주행 모드·에어백은 "지원 안 함"이다. 상세는 [조사 노트 §11.2](PLEOS_PLATFORM_RESEARCH.md#112-시험-앱으로-실제-값-읽기-2026-10-26).
- Nexus에 문서에 없는 `LLM`(2.1.3.2, 서버·온디바이스 LLM 클라이언트) 아티팩트가 있다. 공모전 SDK 목록 밖이고 `PrivilegedApi` 클래스가 있어 3rd-party 사용 가능 여부는 ❓.
- 안 되면 AAOS `PERF_ODOMETER`를 쓴다. Pleos 에뮬레이터 지원은 미확인이다.
- 둘 다 안 되면 최초 1회만 사용자가 계기판 값을 입력하고, 이후에는 트립 거리 증가분을 더한다. 이 경우에도 "매일 입력"은 없어진다.

### 2.3 차량 API와 무관하게 앱이 직접 정의하는 기준

| 기준 | 출처 | 내용 |
|---|---|---|
| 관리항목 기본 교체 주기 | 제조사 정비 매뉴얼의 일반 조건 주기 | 아래 표. 전기차 항목(감속기오일, 배터리 냉각수 등)은 따로 정한다 |
| 진행률 계산 규칙 | 자체 정의 | 거리 진행률과 기간 진행률 중 큰 값. 1 이상이면 정비 필요 |
| 기록 분류 체계 | 자체 정의 | 기본 분류(주유·충전, 정비, 세차, 주차, 통행료, 보험, 세금, 기타) + 사용자 추가 분류 |

모바일 차계부에서 흔한 함정 두 가지는 처음부터 피한다.
- 화면과 알림이 1개월을 다르게(30일과 달력 월) 계산하면 시점이 며칠 어긋난다. 기간 계산은 한 곳에서 달력 월 기준으로 한다.
- 알림의 현재 주행거리를 최신 기록에서 가져오면 늦는다. 항상 차량 값을 쓴다.

### 2.4 범위 밖

중고 시세, 과태료·자동차세 조회, 정비소 전산 연동, 소모품 상품 추천. 외부 계약이나 별도 서버가 필요하고 차량특화성과도 관계가 적다. 필요하면 "확장 계획"(기획서 6번 항목)에 넣는다.

### 2.5 데이터 사용 권한

공모전 이용약관 7조는 출품작에 들어간 데이터에 적법한 사용 권한을 요구한다. 그래서 관리항목 주기와 차종 제원 같은 기준 데이터는 제조사 정비 매뉴얼, 공공 데이터, 차량에서 직접 읽는 값(VIN, AAOS 제원 속성)처럼 출처를 밝힐 수 있는 공개 자료만 쓴다. 제3자 유료 API에서 받은 데이터나 출처를 밝힐 수 없는 데이터는 넣지 않는다.

## 3. 내비게이션 연동 범위

결론: **앱과 차량 내비는 양방향으로 주고받을 수 있다.** 단 내비에서 받는 것은 경로 요약이고, 경로 선(폴리라인)과 장소 검색은 없다.

### 3.1 앱 → 내비 (권한 `NAVI_ROUTE_SEARCH`, 콘솔 사용 가능)

| 할 수 있는 것 | API | 제약 |
|---|---|---|
| 목적지 설정 | `requestRoute(RouteInfo)` | 좌표, 장소 이름, poiId, 주소를 넘긴다. 성공 응답은 접수일 뿐이고 탐색 완료는 `onRoutingCompleted`로 온다 ✅ |
| 경유지 추가·삭제 | `addWaypoint`, `removeWaypoint` | **최대 2개** ✅ |
| 목적지 + 경유지 한 번에 | `requestRouteWithWaypoints` | 목적지 포함 최대 3지점 🟡 |
| 경로 옵션·재탐색·취소 | `changeRouteOption`, `requestReRoute`, `cancelRoute` | 경로 안내 중일 때만. 옵션은 추천·최단거리·최소시간·무료·고속도로 등 7종 ✅ |
| 내비 화면 열기 | `requestNavigationScreen` | 장소 검색, 주변 충전소, 경로 미리보기 등 13종. 권한 `NAVI_CUSTOM_MAP`이 콘솔 목록에 없다 ⚠️ |

### 3.2 내비 → 앱 (권한 `NAVI_ROUTE`, 콘솔 사용 가능)

| 받을 수 있는 것 | 내용 |
|---|---|
| 목적지·경유지 정보 | 이름, 주소, 좌표, **남은 거리·시간, 통행료** ✅ |
| 경로 시작 | 총 거리·시간·통행료, 잔여 연료 ✅ |
| 도착 이벤트 | 목적지·경유지 도착 시 거리, 시간, 이름, 주소. **좌표와 poiId는 없다** ✅ |
| 경로 상태 | 안내 중 여부, 경로 옵션, **도착 시 예상 잔여 연료**, 정체·사고 정보 ✅ (잔여 연료 단위 ❓) |
| 현재 위치 | 좌표, 방향, 주소 ✅ |
| 즐겨찾기·최근 목적지 | 좌표, 이름, 주소. 즐겨찾기는 집·회사 구분 포함 ✅ |
| 제한속도·단속 카메라 | 제한속도는 매초, 과속 여부 포함 ✅ |
| 받을 수 없는 것 | 경로 선(폴리라인), 장소 검색 결과, 주유소·정비소 정보 ✅ |

SDK 바이너리 확인(2026-10-26, NaviHelper 3.0.5 / navi-data 3.0.4): 경로 좌표 목록 필드는 어디에도 없다 ✅. 대신 다음이 있다.
- `onTBTInfo`: 앞으로의 회전 안내 목록(회전 종류, 거리, 설명)
- `RouteStateInfo.trafficStatus`: 정체 구간 목록(경로상 위치 offset, 길이, 평균 속도, 도로명, 시작·끝 교차로명)과 사고·공사 지점 좌표
- `CurrentLocationInfo`: 현재 좌표 + `routeId`, `currentRouteIndex`(경로상 진행 위치)
- 실제로 달린 길은 앱이 떠 있는 동안 현재 위치를 주기적으로 저장해 직접 그린다 🟡(콜백 주기와 에뮬레이터 위치 이동은 미확인).

`requestTrip`은 주행 기록 조회가 아니다. 한 지점까지의 예상 거리·도착시간·예상 에너지 소모를 미리 보는 기능이다 🟡.

### 3.3 차계부 앱에 쓰는 법

1. **정비 시기에 "가는 길에 들르기"**: 엔진오일 교체 시기가 되면, 외부 장소 API(카카오·네이버 등)로 찾은 정비소를 현재 경로의 경유지로 넣는다. 주유소도 같다. 장소 검색은 내비가 안 해 주므로 외부 API가 필요하다.
   - **진행 방향까지 고려한 경로상 주유소·충전소 (2026-10-26 설계안)**: 내비가 경로 선을 주지 않으므로(§3.2) 다음 순서로 찾는다.
     1. 경로 재구성: 내비가 주는 현재 위치·경유지·목적지 좌표와 경로 옵션으로 외부 길찾기 API에서 같은 조건의 경로 선을 받는다. 내비의 총 거리·시간, 회전 안내(TBT)·정체 구간의 도로명과 비교해 같은 경로인지 확인한다.
     2. 후보 추리기: 경로 선에서 일정 폭 안, 현재 진행 위치(`currentRouteIndex`, `heading`)보다 앞, 남은 주행 가능 거리 안에 있는 주유소만 남긴다.
     3. 진행 방향: 우측통행이므로 경로 진행 방향 오른쪽을 우선한다. 고속도로 휴게소는 방향별로 나뉜다.
     4. 진짜 판정: 상위 후보만 "현재→주유소→목적지"와 "현재→목적지"의 시간 차(추가 소요 시간)를 계산한다. 중앙분리대·유턴·IC 출입이 이 값에 그대로 반영된다.
     5. 정렬: 추가 소요 시간 + 가격(오피넷, 전기차는 충전소 공공 API).
     6. 선택하면 `addWaypoint`로 넣고, 내비가 다시 계산한 총 시간으로 실제 추가 시간을 보여 준다.
   - 내비 안내 없이 달릴 때는 현재 진행 방향(`heading`) 앞쪽 부채꼴 안의 주유소로 대신한다.
   - 위험: 외부 지도와 내비 지도(Navi42)의 경로가 다를 수 있다. 추천할 때마다 외부 API를 부르므로 연료 부족 같은 조건에서만 계산한다.
2. **정비소 도착 → 기록 유도**: 경로를 보낼 때 정비소 이름·poiId를 저장해 두고, 도착 이벤트의 이름과 대조한다. 도착 이벤트에 좌표가 없어서 미리 저장해야 한다.
3. **자동 운행일지**: 경로 시작의 통행료 + 도착 이벤트의 거리·시간으로 운행 1건을 만든다. 통행료도 차계부 지출로 들어간다.
4. **연료 부족 사전 경고**: 도착 시 예상 잔여 연료가 낮으면 주유소 경유지를 권한다.
5. **안전운전 점수**: 제한속도와 차속을 비교하고 과속 카메라 경고를 집계한다.

### 3.4 내비 연동의 위험 ❓

**에뮬레이터 실측(2026-10-26)**: 시험 앱에서 `requestRouteWithWaypoints`로 목적지(서울역) + 경유지 1곳(외부 좌표, poiId 빈 문자열)을 보냈다.
- ✅ 내비가 바로 경유지 경유 안내를 시작했다. **운전자 확인창은 뜨지 않았다.** 아래 네 항목 중 내비 앱 유무, 확인창, poiId 비우기는 해소.
- ✅ 받은 값: 경로 시작(경유지까지 42분·21km, 통행료 700원), 회전 안내 전체 목록(회전 종류·구간 거리·"반포IC 방면" 같은 설명), 정체 구간(경로상 위치·길이·평균 속도·도로명·IC명), 목적지 남은 거리·시간, 경로 ID.
- ✅ "도착 시 예상 잔여 연료"는 전기차에서 Wh 값으로 온다(경유지 74640, 목적지 73968, 배터리 용량 77400).
- ⚠️ `onWayPointInfo`가 돌려주는 경유지 좌표는 `0.0`이다. 보낸 경유지 좌표는 앱이 따로 저장해야 한다.
- ⚠️ 내비 앱(Navi42)이 떠 있지 않으면 요청에 응답이 없다. 처음 한 번 내비 앱이 실행된 상태여야 한다 🟡.
- 에뮬레이터에서 지도 타일은 검게 나온다(소프트웨어 렌더링). 안내 카드와 회전 안내는 정상이다.

- **에뮬레이터에 내비 앱이 있는지 모른다.** 샘플 README는 "호환 내비 앱이 기본 내비로 설정돼 있어야 한다"고 요구한다. 없으면 2차 PT에서 내비 기능을 실제로 시연할 수 없다. **에뮬레이터를 띄워서 가장 먼저 확인할 항목이다.**
- 경로를 보낼 때 운전자에게 확인창이 뜨는지 모른다.
- 외부 장소를 보낼 때 poiId를 비워도 되는지 모른다.
- 샘플 앱에 문서에 없는 권한 `NAVI_CUSTOM_ROUTE`, `NAVI_CUSTOM_ETC`가 있다.

### 3.5 과거 경로·주행 기록을 넘겨주는 API는 없다

차량이나 내비가 이미 쌓아 둔 주행 이력(언제, 어디서 어디로, 몇 km, 연료 얼마)을 앱이 조회할 수 있는지 Pleos 문서 전체를 확인했다(2026-10-25). **공모전에서 쓸 수 있는 것 중에는 없다** ✅. 있는 것은 현재 시점의 누적값과 지금 안내 중인 경로뿐이다.

| 후보 | 주는 것 | 과거 이력 | 공모전 사용 |
|---|---|---|---|
| Vehicle SDK Odometer·Fuel | 총 주행거리, 이번 주행·누적·주유 후의 거리·시간·연비 | ✗ 현재값만 | ✅ |
| NaviHelper | 최근 목적지·즐겨찾기 목록(좌표·이름·주소), 이번 안내의 도착 이벤트(거리·시간) | 목적지 목록만. 날짜·거리·경로는 없다 | ✅ |
| Vehicle SDK `getTelltalesInfo` | 경고등 묶음 | ✗ | ✗ 시스템 앱 전용 권한. 공식 샘플도 막아 뒀다 |
| Pleos Platform SDK | OEM 서버 연동, 보정 위치 등 | ✗ | ✗ 시스템 앱 전용 권한 |
| Vehicle Data API | **주행(trip) 단위 시계열 이력**. 한 번에 최대 7일 | ✅ | ✗ 유럽 한정, 실차 VIN 필요 |
| Fleet API | 실시간 주행거리·시동 Webhook. Trip 이력은 "Coming soon" | 예정 | ✗ 제휴 계약 필요 |

Vehicle SDK의 `TripStatistics`는 이름과 달리 주행 이력이 아니다. 값 하나를 이번 주행·누적·주유 후로 나눠 담는 내부 타입이다 ✅.

**그래서 주행 기록은 앱이 직접 쌓는다.** 방법은 다음과 같다.

1. **앱을 열 때마다 스냅샷 비교**: 총 주행거리, 주유 후 거리, 누적 연비와 시각을 저장한다. 앱이 꺼져 있던 동안 달린 거리도 다음 실행 때 총 주행거리 차이로 복원된다. 경로와 정확한 출발·도착 시각은 알 수 없다. 백그라운드 상주가 필요 없어서 성능 가이드에도 맞는다.
2. **주행 구간 나누기**: 앱이 떠 있는 동안 이번 주행 거리를 구독하다가 값이 0으로 돌아가면 직전 주행을 1건으로 확정한다. 주유 후 거리가 0으로 돌아가면 주유로 보고 기록을 권한다 🟡.
3. **목적지 붙이기**: 내비 도착 이벤트의 거리·시간·이름과 최근 목적지 목록을 주행 1건에 연결한다.

기획 관점에서는 "차가 기록을 넘겨준다"가 아니라 **"앱이 차량 값을 읽어 자동으로 기록한다"**로 표현해야 사실과 맞다(조사 노트 §13.1의 정직 표시 원칙).

## 4. 기획 방향 제안

모바일 차계부를 그대로 옮기는 데서 끝나면 "모바일 앱을 차에 띄운 것"이 된다. 심사 기준에 맞추려면 **입력이 사라진 차계부**를 중심에 둔다.

| 축 | 모바일 차계부 | 이 앱 |
|---|---|---|
| 기록 | 사람이 입력 | 차가 기록하고 사람은 확인만 한다(주유 감지, 운행일지, 주행거리) |
| 정비 판단 | 주기 추정 | 주기 + 차량 센서 경고 + 운전 패턴 |
| 행동 연결 | 앱 안에서 예약 | 내비 경유지로 바로 들른다 |

이 구조라면 Vehicle State와 NaviHelper가 모두 핵심 기능에 들어가서 기술 활용성 점수도 받을 수 있다.

### 4.1 개발 가정 (2026-10-25)

미확인 항목은 아래처럼 된다고 가정하고 개발한다. 각 가정에는 안 될 때의 대체 경로를 두고, 데이터를 읽는 부분 뒤에 실제 구현과 Fake 구현을 함께 두어 바꿀 수 있게 한다([아키텍처](ARCHITECTURE.md) 2.3절).

| 가정 | 안 될 때 |
|---|---|
| `getCurrentDistanceDriven`으로 총 주행거리를 읽을 수 있다 | AAOS `PERF_ODOMETER` → 최초 1회 입력 + 트립 증가분 |
| 주유 후 거리가 주유 시 0으로 돌아간다 | 연료 % 상승만으로 주유를 감지한다 |
| 에뮬레이터에서 NaviHelper가 동작한다 | 내비 연동은 Fake로 시연하고 기획서와 PT에 표시한다 |
| 외부 장소를 poiId 없이 경유지로 보낼 수 있다 | 내비 검색 화면(`SearchPlace`)으로 넘긴다 |

### 4.1.1 연료차·전기차 동시 지원 (2026-10-26 결정)

에뮬레이터 차량이 전기차 구성이라 연료·연비 값이 나오지 않는다([조사 노트 §11.2](PLEOS_PLATFORM_RESEARCH.md#112-시험-앱으로-실제-값-읽기-2026-10-26)). 그래서 두 종류를 함께 지원한다.

- 차량에 에너지 종류(연료/전기)를 두고 처음부터 데이터 구조에 넣는다. 주유·충전은 "에너지 기록" 하나로 묶는다.
- 공통: 주행거리, 관리항목 주기, Gleo 기록, 커뮤니티, 워키토키. 순위는 같은 차종끼리라 섞이지 않는다.
- 나뉘는 것: 주유/충전 감지, 효율(연료차는 차량 연비, 전기차는 앱이 계산), 관리항목 목록, 주유소/충전소, 단위·입력 폼.
- 1차 시연은 전기차 실제 신호로 하고, 연료차는 같은 구조에 데모 데이터로 보여 준다.
- 추가 공수 추정: 1인 8~12일(전체의 약 20~30%).

### 4.2 디자인 전제

화면은 [UI 디자인 가이드](UI_DESIGN_GUIDE.md)(Pleos Connect UI Design Guide 정리)를 전제로 설계한다. 기획 단계에서 특히 지킬 것은 다음과 같다.

- 모든 화면을 **Portrait와 Landscape 두 레이아웃**으로 만든다. 가장 작은 Portrait 창은 약 628×800이다.
- **Light와 Dark 테마**를 모두 지원하고, 색은 Pleos 토큰으로만 쓴다.
- 글자가 모바일보다 훨씬 크다. 본문 최소 26, 제목 32 이상이다. 한 화면에 담을 정보량을 모바일 기준으로 잡지 않는다.
- 버튼, 팝업, 토스트, 탭, 스위치는 Pleos 컴포넌트를 쓴다. 팝업은 **확인 버튼이 왼쪽**이다.
- 핵심 정보는 1~2초 안에 읽혀야 하고, 장식 애니메이션은 쓰지 않는다. 대비는 4.5:1 이상이다.
- 아이콘에는 텍스트 라벨을 붙인다.

### 4.3 팀 기능안 실현 가능성 검토 (2026-10-25)

팀이 고안한 기능을 지금까지의 조사와 맞춰 본 결과다. ✅ 사용 가능 SDK로 가능, 🟡 조건부·우회 필요, ✗ 공모전 범위에서 불가.

| 음성인식 정비·지출 기록 | 🟡 | STT SDK는 준비 중. Gleo는 아래 참고. 대체로 Android 표준 음성인식 |
| 커뮤니티 유저 간 워키토키 | 🟡 | 초대한 친구·그룹끼리만 연결(2026-10-26 결정). 마이크는 Android 표준 녹음(에뮬레이터 마이크 설정 있음), 전송은 자체 중계 서버. 오디오 포커스 정책 준수. **주행 중 사용 허용 여부 ❓**: 사람 간 소통은 Social/Communication 카테고리 목적이고 Mobility Services 주행 중 예시에 없다 |
| 사고 데이터 자동 기록 | ✅ | 에어백 전개 시점의 시각·위치(내비 현재 위치)·차속·주행거리를 저장. 빌트인캠 영상은 아래 ✗ 항목 참고(2026-10-26 결정: 데이터 기록으로 가고 영상은 확장 계획) |
| 드라이브 모드·운전습관 기반 연비 개선 추천 | 🟡 | 주행 모드 + 순간·누적 연비 + AAOS 차속(급가속·급감속은 차속 변화로 계산). 규칙 기반 추천. 앱이 떠 있을 때만 수집 |
| 하이패스 통행료 자동 기록 | 🟡 | 2026-10-26 추가. 앱이 하이패스 거래를 읽을 API가 없다(조사 노트 §11.2). 대체: 내비 경로 시작 이벤트의 예상 통행료(`tollFare`)를 운행 기록에 붙인다. 실제 결제 금액이 아니라 예상치라고 표시한다. 하이패스 거래 접근 방법은 설명회에서 묻는다 |
| 시동·주행 시작 감지 | 🟡 | 2026-10-26 추가. 시동 상태 API가 없다. 대체: 기어 P→D 전환 + 총 주행거리 증가 + 앱 재실행으로 "주행 시작/종료"를 판단한다 |
| 공회전 분리 | 🟡 | 2026-10-26 추가. 정차(차속 0) + 기어 P/N, 또는 D에서 브레이크를 밟은 채 일정 시간 이상이면 공회전으로 본다. **전기차는 정차 중 배터리 에너지 감소를 직접 재서 정확히 뺄 수 있다.** 연료차는 차량 누적 연비에 공회전이 섞여 있고 연료량이 정수 %라서 공회전 연료를 잴 수 없다. 공회전 시간은 정확하고, 연료량은 추정치로만 보여 준다 |
| Gleo 호출 함수 | 🟡 | 함수 최대 3개, 7초 내 응답. 어느 기능을 등록할지 결정 필요. 공모전 SDK 목록 밖이라 등록·에뮬레이터 지원 ❓ |
| 오토큐·블루핸즈 예약 | 🟡 | 공개 예약 API 없음. 예약 웹 페이지 연결, 정비소 위치는 내비 목적지로 보내기 |
| 보험 등록 → 긴급출동 | 🟡 | 보험사 API 없음. 등록한 보험사의 긴급출동 번호 표시. 차량에서 전화 기능은 제한될 수 있다 |
| 주행거리 자동 기록 | ✅ | `getCurrentDistanceDriven`(총 주행거리, km) |
| 경로 기록 | 🟡 | 경로 선(폴리라인)은 받을 수 없다. 출발·목적지·거리·시간 단위로 기록한다 |
| 운전 점수 | 🟡 | 내비 제한속도(매초) + AAOS 차속, 과속 카메라 경고. 앱이 떠 있을 때만 수집 가능 |
| 주행 모드별 연비 | ✅ | `getCurrentDrivingModeState` + 연비 샘플링. 앱이 떠 있을 때만 수집. 단위 L/100km |
| 대여 모드 | ✅ 자체 | 앱 로직. 개인 기록 숨김, 대여 기간 주행만 따로 기록 |
| 내비와 쌍방향 주유소 경유 | ✅ | NaviHelper 경유지 추가 + 오피넷 주유소·유가 |

**필요 기능**

| 기능 | 판정 | 내용 |
|---|---|---|
| Gleo 음성 변환 데이터 수신 | 🟡⚠️ | Gleo는 **음성 원문을 앱에 넘기지 않는다.** 앱이 함수(최대 3개)를 등록하면 Gleo가 파라미터를 채워 호출하는 방식이다. 예: `RECORD_EXPENSE(category, amount)`. 결과적으로 구조화된 기록은 받을 수 있다. 다만 공모전 SDK 목록에 없고 등록 절차·에뮬레이터 지원이 미확인이다 |
| NaviHelper 경로 대신 지정 | ✅ | `requestRoute`, `addWaypoint`(경유지 최대 2개) |
| 현 경로 연비 기록 | 🟡 | 경로 시작 이벤트와 도착 이벤트 시점의 누적 연비·연료·주행거리를 비교해 계산한다 |
| 차량 연비 | ✅ | Fuel 도메인 |
| 남은 주행거리 | 🟡 | Pleos SDK 조회 API는 문서에서 숨겨졌다. AAOS `RANGE_REMAINING`, 내비의 도착 예상 잔여 연료, 또는 연료 % × 탱크 용량 × 연비로 계산 |
| 에어백 전개 상태 | ✅ | `hasSeatAirbagBeenDeployed` |

**핵심 플로우**

| 플로우 | 판정 | 내용 |
|---|---|---|
| 정비소 목적지 → 도착 → 재시동 시 정비 내용 질문 | ✅ / 🟡 | 도착 이벤트 ✅. 도착 이벤트에는 좌표·poiId가 없어서 경로 안내 중에 목적지 정보를 미리 저장하고 이름으로 정비소인지 판단한다. 재시동은 AAOS 시동 상태나 앱 재실행으로 감지 🟡 |
| 사고 시 보험사 연락 권유 | ✅ / 🟡 | 에어백 전개로만 감지한다. 충돌 감지 API는 없다 |
| 주행거리 일정 미만 시 주유소 표시 | 🟡 | 남은 주행거리는 위 방법으로 계산. 주유소는 오피넷 |
| 주유소 체류 → 주유 기록 안내 | 🟡 | 위치는 FusedLocation이 준비 중이라 내비 현재 위치로 받는다. **체류 시간보다 "주유 후 거리 초기화 + 연료 % 상승"이 더 정확하다.** 연료 신호로 주유를 확정하고, 위치는 어느 주유소인지 찾는 데 쓴다 |
| 빌트인캠 사고 영상 기록 | ✗ | Pleos Connect SDK에 카메라·블랙박스 API가 없다. 카메라 API는 SDV OS(차량 OS 레벨, Rust/C++)에만 있고 차량 앱용이 아니다. 확장 계획으로 돌린다 |
| 차량 진단 → 정비 권유 | 🟡 | 쓸 수 있는 진단은 엔진 이상, 오일류 레벨, 타이어 저압, 워셔액이다. 고장 코드(DTC)나 경고등 묶음(`getTelltalesInfo`)은 시스템 앱 전용이라 못 쓴다 |
| 스킨 마켓 + 커뮤니티 | 커뮤니티 ✅ 자체 / 스킨 마켓 보류 | 자체 서버. 글 작성 같은 키보드 입력은 정차 중에만. 스킨 마켓은 2026-10-26 보류(위 "차량 꾸미기" 참고) |
| 이전 주행거리 기록 호출 → 언제 시작해도 연동 | 🟡 | **과거 주행 이력을 주는 API는 없다(§3.5).** 대신 앱을 처음 켠 순간의 총 주행거리를 기준으로 삼고, 이후 앱을 안 연 기간의 주행은 총 주행거리 차이로 복원한다. 앱 설치 전 기록은 모바일 차계부 가져오기로 보완한다 |
