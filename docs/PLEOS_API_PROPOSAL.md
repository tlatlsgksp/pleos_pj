# Pleos API 개방 제안

차곡을 만들며 필요했지만 지금 3rd-party 앱에 열려 있지 않은 기능을 정리한다. 기획서 6.3 확대 계획과 2차 PT의 근거 자료로 쓰고, 설명회·기술지원 문의에도 쓴다.

- 작성일: 2026-10-26
- 근거: Pleos Connect 에뮬레이터(이미지 2026-10-16 빌드)에서 시험 앱으로 확인한 결과([조사 노트 §11](PLEOS_PLATFORM_RESEARCH.md)), SDK 바이너리(Vehicle 2.3.2, NaviHelper 3.0.5)
- 원칙
  - 핵심 기능은 지금 열린 API로 만든다. 이 문서의 항목은 "열리면 더 좋아지는 것"이다.
  - 항목마다 **지금의 우회 방법**과 **플랫폼이 걱정할 안전·개인정보 장치**를 함께 적는다. 제안이 받아들여지기 쉽게 하기 위해서다.

## 1. 요약

| # | 열어 주길 바라는 것 | 지금 상태(확인 근거) | 우리 기능 | 지금의 우회 |
|---|---|---|---|---|
| 1 | 주행 화면 차량 테마(랩·색상) | 주행 화면(DrivingView)은 시스템 앱. 외부 제어는 날씨뿐이고 그것도 `signature` 권한 | 차량 스킨 | 앱 속 3D + 실내 앰비언트 조명 |
| 2 | 지난 주행 이력 | 현재 누적값만 있음. 이력 API는 유럽 한정 Vehicle Data API뿐 | 앱이 꺼져 있던 기간의 운행일지 | 누적 주행거리·에너지 차이로 합계만 복원 |
| 3 | 시동·전원 상태 이벤트 | SDK에 `IgnitionState` 상수만 있고 값을 주는 함수가 없음. AAOS `IGNITION_STATE` 미지원 | 주행 시작 감지, 정비 후 재출발 질문 | 기어·주행거리·부팅 신호 조합 |
| 4 | 전원 ON 시 앱 화면 열기(사용자 설정) | 부팅 신호는 오지만 화면 띄우기는 시스템이 막음(`BAL_BLOCK`). 직전 앱도 복원되지 않음 | 시동 시 오늘의 차 상태 보여 주기 | 백그라운드 서비스 + 알림 |
| 5 | 하이패스 거래 이벤트 | 차량 내부 ETCS 상태에 거래(요금소·잔액)가 있지만 SDK `Toll`은 안내 음량만 줌 | 통행료 자동 기록 | 내비 예상 통행료 |
| 6 | 핸들 사용자 지정 키 할당 | 키 감시 권한(`HID_INPUT_MONITOR`)은 `signature`. 사용자 지정 키 속성(`HW_CUSTOM_INPUT`) 없음. 앱이 화면 앞에 있을 때만 키를 받음 | 워키토키 누르고 말하기 | 자동 답장 창, Gleo 호출 |
| 7 | Gleo 앱 함수 등록 | 비서 앱과 App Schema 방식은 존재(내비 앱이 사용). Gleo의 `APP_ACTION` 권한이 `signature` | 음성 기록 | 앱 마이크 + 음성인식 |
| 8 | 내비 경로 형상(좌표 목록) | NaviHelper 3.0.5 데이터 어디에도 좌표 목록이 없음. 회전 안내·정체 구간·진행 위치만 있음 | 경로상 주유소·충전소 | 외부 길찾기로 추가 소요 시간 계산 + 경유지 끼워 넣기 |
| 9 | 경고등 묶음 | `getTelltalesInfo`는 시스템 앱 전용 | 정비 권유 정확도 | 개별 경고 6종 |
| 10 | 백그라운드 기록 허용 기준 | 포그라운드 서비스는 동작함. 앱 마켓 정책상 허용 범위가 문서에 없음 | 앱을 안 켜도 쌓이는 기록 | 시동 시 1회 + 주기 스냅샷 |

## 2. 항목별 제안

### 2.1 주행 화면 차량 테마 (랩·색상)

- **왜**: 운전자가 가장 오래 보는 화면이 주행 화면이다. 화면 속 차를 꾸미는 기능은 다른 제조사(테슬라)가 순정 기능으로 제공한다 `[근거 필요: 기능 범위·출처 확인]`. 외부 개발자에게 열면 스킨 마켓·커뮤니티 생태계가 생긴다.
- **예시**
  - **법인 차량**: 회사가 로고 랩과 회사 대표색 조명을 묶은 스킨을 소속 차량에 배포한다. 운전자가 차에 타면 주행 화면의 차에 회사 랩이 입혀져 있고 실내 무드등이 회사 색으로 켜진다.
  - **개인**: 좋아하는 색·패턴 랩을 고르거나 커뮤니티에서 받은 스킨을 적용한다.
- **제안 형태**: 자유 이미지가 아니라 **차종별 랩 템플릿(UV 전개도)과 색상 팔레트 형식**을 정하고, 앱이 그 형식의 테마 파일을 제출하면 주행 화면이 적용한다. 테마는 앱 마켓 심사를 거친다.
- **안전·브랜드 장치**: 승인된 형식만 받는다. 경고등·안내 표시 영역은 테마가 덮지 못한다. 주행 중에는 테마를 바꿀 수 없다.
- **지금의 우회**: 앱 속 3D 차량에 같은 스킨을 입히고, 실내 앰비언트 조명 색을 `setAmbientLightBrightnessColor`로 맞춘다(에뮬레이터에서 차량 HAL까지 명령 전달 확인). 시제품은 만들었지만 실차 특징을 살린 3D 모델이 없어 2026-10-26 보류했다([archive/skin-prototype](../archive/skin-prototype/README.md)). 이 기능이 열리면 바로 꺼내 쓴다.

### 2.2 지난 주행 이력

- **왜**: 앱을 매번 켜지 않아도 운행일지가 빠짐없이 남아야 차계부가 완성된다.
- **제안 형태**: 최근 N일의 주행(trip) 단위 요약(시작·종료 시각, 주행거리, 에너지 사용량, 출발·도착 좌표)을 읽기 전용으로 준다. 유럽용 Vehicle Data API의 trip 단위 이력과 같은 형태를 차량 안 SDK로 연다.
- **안전·개인정보 장치**: 사용자 동의 후에만, 기간 제한, 좌표는 별도 권한으로 분리.
- **지금의 우회**: 누적 주행거리·에너지 차이로 합계만 복원한다. 언제·어디로 갔는지는 남지 않는다.

### 2.3 시동·전원 상태 이벤트

- **왜**: "주행 시작", "정비 후 첫 출발" 같은 순간에 기록을 묻는 것이 입력 없는 차계부의 핵심이다.
- **제안 형태**: SDK에 이미 있는 `IgnitionState`(LOCK/OFF/ACC/ON/START)를 읽기·구독 API로 연다.
- **안전·개인정보 장치**: 읽기 전용.
- **지금의 우회**: 기어 P→D 전환, 총 주행거리 증가, 부팅 신호를 조합한다.

### 2.4 전원 ON 시 앱 화면 열기

- **왜**: 차에 타자마자 "오늘 엔진오일 교체 시기예요" 같은 정보를 보여 주면 사용성이 크게 좋아진다.
- **제안 형태**: 시스템 설정에 "시동 시 실행할 앱" 항목을 두고 사용자가 고른 앱 하나만 실행한다. 휴대폰의 기본 앱 지정과 같은 방식이다.
- **안전 장치**: 사용자가 직접 켠 경우에만, 앱 하나만, 정차 상태에서만.
- **지금의 우회**: 부팅 시 백그라운드 서비스가 스냅샷을 찍고 알림을 띄운다. 운전자가 알림을 눌러 연다.

### 2.5 하이패스 거래 이벤트

- **왜**: 통행료는 사람이 거의 기록하지 않는 지출이라 자동 기록의 효과가 크다.
- **제안 형태**: 거래 발생 이벤트(시각, 요금소 이름, 금액)를 읽기 전용으로 준다.
- **개인정보 장치**: 카드 번호·잔액은 제외한다.
- **지금의 우회**: 내비가 경로 시작 때 주는 예상 통행료를 쓰고 "예상"이라고 표시한다.

### 2.6 핸들 사용자 지정 키 할당

- **왜**: 주행 중 화면을 누르지 않고 워키토키·음성 기록을 시작할 수단이 필요하다.
- **제안 형태**: 시스템 설정에서 사용자 지정 키에 앱을 할당하면, 그 키 입력을 해당 앱에 전달한다(누름·뗌 구분 포함).
- **안전 장치**: 사용자가 할당한 앱 하나만 받는다. 다른 앱의 키 입력은 볼 수 없다.
- **지금의 우회**: 메시지를 들은 뒤 몇 초간 열리는 자동 답장 창, Gleo 음성 호출.

### 2.7 Gleo 앱 함수 등록

- **왜**: 음성으로 기록하는 것이 주행 중 가장 안전한 입력이다.
- **제안 형태**: App Schema 등록 절차를 3rd-party 앱에 공개한다. 함수 3개 제한은 유지해도 된다.
- **지금의 우회**: 앱 마이크로 녹음하고 음성인식으로 처리한다.

### 2.8 내비 경로 형상

- **왜**: 경로 위 장소를 정확히 고르려면 경로 선이 필요하다.
- **제안 형태**: 현재 안내 경로의 단순화한 좌표 목록(예: 500m 간격)을 준다.
- **안전 장치**: 경로 안내 중일 때만, 앱이 화면에 있거나 서비스가 실행 중일 때만.
- **지금의 우회**: 외부 길찾기로 후보마다 추가 소요 시간을 계산하고, 고른 곳을 경유지로 넣는다. 내비가 다시 계산한 시간으로 확인한다.

### 2.9 경고등 묶음

- **왜**: 개별 경고 6종보다 경고등 전체를 보면 정비 권유가 정확해진다.
- **제안 형태**: 경고등 상태를 읽기 전용으로 준다.
- **지금의 우회**: 엔진 이상, 오일류 레벨, 타이어 저압, 워셔액 경고만 쓴다.

### 2.10 백그라운드 기록 허용 기준

- **왜**: 성능 가이드는 백그라운드 작업 최소화를 요구하지만, 차계부는 앱을 안 켜도 기록이 쌓여야 한다.
- **제안 형태**: 허용되는 백그라운드 작업 유형(예: 시동 시 1회, 15분 주기 스냅샷)과 자원 한도를 문서로 정한다.
- **지금의 우회**: 시동 시 1회와 주기 스냅샷만 하고, 촘촘한 수집은 앱을 띄워 둔 동안만 한다.

## 3. 설명회·문의 질문

1. 공모전에서 이런 API 개방 제안을 심사나 이후 개방 논의에 반영하는가?
2. 주행 화면 차량 테마를 외부에 열 계획이 있는가?
3. 실차에 사용자 지정 키가 있는가? 앱에 할당할 수 있는가?
4. 실차의 전원 켜기는 부팅인가, 절전 복귀인가? 시동 시 앱 실행 설정을 둘 계획이 있는가?
5. 앱 마켓 정책상 포그라운드 서비스와 부팅 시 실행은 어디까지 허용되는가?
6. Gleo App Schema를 3rd-party 앱이 등록하는 절차가 있는가?
7. 하이패스 거래 정보를 앱에 줄 계획이 있는가?
8. 탑재 차종(더 뉴 그랜저, 아이오닉 3)의 공식 3D 모델을 공모전 참가팀에 제공할 수 있는가? 주행 화면에 쓰는 차량 에셋을 앱 안 스킨 미리보기에 써도 되는가?
9. 에뮬레이터 차량은 전기차 구성인데, 첫 탑재 차종인 그랜저(가솔린·하이브리드)에 맞춘 연료차 에뮬레이터 설정이나 이미지가 있는가?
